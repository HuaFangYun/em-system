# EmSys.Api.Core 0.1.0-alpha.11

Date: 2026-10-13
Previous: 0.1.0-alpha.10

## Summary
Adds a log engine, enabled by the host with builder.AddLogServer(). It records data audit of modules in the same transaction as the data, engine audit of sign-in, passwords, users, roles, robots, settings and deletions, and telemetry (diagnostic lines, errors grouped by fingerprint, request access lines and logs sent by WPF/MAUI clients). Database scripts must be installed before the engine is enabled, and module audit groups are registered with builder.AddAudit().

## Breaking changes

- `EmDbContext` now overrides `OnModelCreating` to map the shared audit outbox entity. Derived contexts that override `OnModelCreating` must call `base.OnModelCreating(modelBuilder)`.
- `ITokenServices.RevokeAllAsync(string cUserId)` became `RevokeAllAsync(string cUserId, string? reason = null)`. Callers compile unchanged; classes that implement the interface must add the parameter.

## New features

- `EmAppBuilder.AddLogServer()` registers an `ILoggerProvider` that stores telemetry through a bounded in-memory queue and a background writer (disk segments under `storage.logPath` while the store cannot be written, resent later), the `ILogServices` and `IAuditServices` actions, their claims and the engine audit groups (`System.*`). Calling it twice throws. Without it, audit entries are discarded and telemetry only goes to the console.
- `EmAppBuilder.AddAudit("<Group>", a => ...)` registers a module audit group: title, entry kinds (optionally with a required reason or reportable by clients), read rule (`CanRead` / `CanReadClaim`), minimum retention and extra databases. The prefix `System.` is reserved for the engine. `EmAppBuilder.AddScoped<T>()` registers module helpers such as an `InvoiceAudit` wrapper.
- `IAuditWriter`: `AddEntry` parks an entry that is saved by the next `SaveChanges` of an engine context in the same request, so it commits or rolls back with the data; `Use(context)` directs entries when a request saves through several contexts; `WriteNowAsync` writes in its own transaction; `SaveAsync(context)` covers bulk paths. Actor, session, request id, client address and application are filled from the request.
- `AuditDiff.Of(before, after, ignore, secret)` builds field-by-field changes; secret properties record only `(set)`/`(changed)`/`(cleared)`.
- `IAuditReader` for server code (`ByDocAsync`, `ByDocNoAsync`, `ByTypeAsync`, `SinceAsync`, `QueryAsync`), merging the active store, read stores and outboxes not yet shipped.
- Engine audit is written for sign-in (including failed sign-ins), sign-out, session revocation, password changes and resets, users, roles, robots, settings, and deletions in the container registry, NuGet server and object storage.
- Errors are grouped by fingerprint (exception type and top application frame) with the triage states New, Acknowledged, Resolved and Ignored; a resolved group seen again becomes New.
- Every request carries a unique request id (`instance:id:start`) in its trace lines and logging scope, shared with the audit entries of that request; the caller's identity is added to the scope after the gate.
- Log stores: the core database by default, or another SQL Server, MySQL or PostgreSQL database configured from Log Manager (**Test**, **Prepare** with a one-time owner credential, **Save**; Write/Read/Detached roles). The store scripts are embedded in the package. `EM_LOG_DB_CONNECTION` and `EM_LOG_DB_PROVIDER` override the write store.
- A daily retention job (default 02:00) with per-level telemetry rules, a telemetry size limit, error group expiry, and audit retention that never goes below a group's minimum.
- New configuration in `emapi-config.json`: `storage.logPath` and the `log` section (`storeRequestStartLines`, `queueCapacity`, `outboxMaxMb`, `appName`), exposed as `EmAppBuilder.LogSettings`.
- Request trace lines of the log module itself (`core.log`) are written at Debug level so reading logs does not create log rows about itself; 5xx stays an error.

## Upgrade notes

- Before enabling `AddLogServer()`, run `doc/sqlscript/mssql/tables/070-log-audit.sql` and `071-log-store.sql` on the core database (after the other `tables/` scripts). MySQL and PostgreSQL versions are in `doc/sqlscript/mysql/tables/` and `doc/sqlscript/postgresql/tables/`. Startup fails with a clear message when the schema is missing or older than the engine.
- A module database whose context writes audit entries also needs `070-log-audit.sql`.
- One API instance per log store.
- Guide: `doc/engine/engine-log.md`.
