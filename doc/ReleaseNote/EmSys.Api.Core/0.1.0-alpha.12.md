# EmSys.Api.Core 0.1.0-alpha.12

Date: 2026-10-15
Previous: 0.1.0-alpha.11

## Summary
Adds managed buckets to object storage. A module declares the bucket it needs with builder.AddManagedBucket(name, owner, description, ...), and at startup object storage creates it with its own policy on a default volume, or adopts an existing bucket of the same name, so the module can use IObjectStore without any setup by an administrator. Administrators keep the infrastructure (volumes, replicas, retention, quotas) but cannot change the contents, access or policy of a managed bucket. No database change is required.

## New features

- `EmAppBuilder.AddManagedBucket(name, owner, description, o => ...)` declares a bucket owned by a module. `owner` (1–100 characters) is shown as "Managed by ..."; `description` (10–500 characters, written for administrators) says what the bucket holds and what changing its volumes or quotas affects. `ManagedBucketOptions` sets the starting values of the bucket's policy: `Access` (default `Private`), `MaxObjectBytes`, `KeepVersions`, `KeepDays`, `QuotaBytes`, `QuotaObjects` and `Note`. Declarations may come before or after `AddObjectStorage()` and are ignored when object storage is off; declaring the same name twice throws.
- At startup object storage creates each declared bucket with a policy named `<bucket> (managed)` on the default volume, or adopts an ordinary bucket of the same name with its contents (a policy shared with other buckets is copied first). Owner and description are updated when they change and the declared access is enforced at every startup; the other policy values are used only when the policy is created, so later changes by an administrator are kept.
- `AddObjectStorage(o => o.DefaultVolumePath = ...)` sets the folder of the volume created for managed buckets, absolute or relative to the content root (default `data/objectstore`). The volume is created once, only when a managed bucket needs a new policy. `AddObjectStorage()` without options still works.
- Management actions protect managed buckets: upload (checked before the content is read), delete, restore and version purge of objects answer 409, as do moving the bucket to another policy, giving its policy to another bucket, changing the access of a managed policy, and deleting the bucket or its policy. Browsing, object info, versions and download stay available, and volumes, replicas, retention, quotas, maximum object size, state and notes stay editable. `IObjectStore`, retention, garbage collection, replication and repair work as before.
- A managed bucket that the running API no longer declares stays locked and is reported as not declared. `PostMeta_StoreBucketRelease` turns it into an ordinary bucket with an ordinary policy, keeping its contents.
- New object storage audit entries: managed bucket created, adopted, access enforced and released.

## Upgrade notes

- No table change and no migration: owner and description are kept in the bucket's existing additional data. The object storage schema version stays 1.
- Optional: re-run `doc/sqlscript/mssql/views/vi_StoreBucket.sql` to read the owner and description of buckets from SQL. The engine does not need it.
- See `EmSys.Libs` 0.1.0-alpha.12 for the contract changes and `EmSys.Ui.Wpf.Core` 0.1.0-alpha.12 for the Object Storage Manager screen.
- Guide: section "Managed buckets" in `doc/engine/engine-object-storage.md`.
